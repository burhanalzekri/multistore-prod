# المرحلة الأولى — الأساس والواجهة المعتمدة (مجمّدة بصرياً)

## قرار التجميد

اعتمد المستخدم تصميم المرحلة الأولى وطلب تثبيته قبل متابعة بقية المراحل. تحفظ هذه النسخة هوية الواجهة البيضاء البنفسجية/السماوية مع الوضع الداكن الاختياري وبطاقة التحليلات التفاعلية. لا تُغيّر الهوية أو الأقسام من دون طلب جديد؛ يُسمح بتحسينات أداء داخلية لا تبدّل المظهر.

- Next.js 15 App Router وTypeScript strict وBun 1.4.2.
- Tailwind CSS 3 مجمّع عبر PostCSS؛ لا CDN.
- Prisma 6 وPostgreSQL، مع توسيع المخطط التجاري في المرحلة 2.
- إعداد AVIF/WebP وCloudinary، محلل الحزم، Lighthouse CI، ميزانيات الأداء وتهيئة Sentry الخادمية الاختيارية.
- Landing عربية RTL ذات 11 قسماً ومولّدة ثابتاً.
- بطاقة Bento للتحليلات بفترات 7/30/90 يوماً وتنزيل CSV، ومفتاح وضع فاتح/داكن يحفظ اختيار الزائر محلياً.
- الحركة والاقتراحات ومؤشر المزاج والعدادات تُضاف تدريجياً عبر `public/landing-interactions.js`، من دون React hydration لهذه التفاعلات.

## حدود بيانات المعاينة

الأرقام وأسماء المتجر والطلبات ومؤشرات المبيعات توضيحية بالكامل. فلاتر الرسم وملف CSV تعرض بيانات نموذجية، لا تحليلات من متجر أو قاعدة بيانات. الاقتراح السياقي محلي بحسب القسم، ومؤشر المزاج اختيار تجريبي؛ لا يُحفظ نشاط الزائر ولا يُرسل إلى الخادم. ربط التحليلات الحية مرحلة لاحقة.

## اختبارات النسخة النظيفة

- `bun run typecheck` — ناجح.
- `bun run lint` — ناجح.
- `node --check public/landing-interactions.js` — ناجح.
- `bun run build` بعد حذف `.next` وإعادة بنائه من المصدر — ناجح؛ `/` ثابتة.
- Playwright: الوضع الداكن وحفظه وإعادة تحميله، فلاتر التقارير وتنزيل CSV، لا أخطاء صفحة، ولا قص أفقي عند عرض 390px — ناجح.
- اجتياز أقسام الصفحة كلها عند التمرير — ناجح.
- فحص HTTP محلي وعام للمعاينة — `200`.

محاكاة هاتف Lighthouse CI على المسار `/`، ثلاث تشغيلات؛ القيم التالية وسيط التشغيلات. نتيجة الحاسوب من تشغيل منفرد منفصل:

| Performance | 97/100 | 100 طلب المستخدم، و>98 بالمواصفة | غير محقق |
| FCP | 1,063 ms | <800 ms | غير محقق |
| LCP | 2,561 ms | <1,000 ms | غير محقق |
| Speed Index | 1,063 ms | <1,500 ms | محقق |
| TBT | 20 ms | <100 ms | محقق |
| CLS | 0 | <0.02 | محقق |
| JavaScript المنقول | 111,184 bytes | <100,000 bytes | أعلى من السقف بـ11,184 bytes |
| إجمالي الموارد المنقولة | 287,130 bytes | <500,000 bytes | محقق |

فحص الحاسوب المنفرد على build نفسه: **100/100**، FCP 290ms، LCP 569ms، TBT 0ms، CLS 0.00025، Speed Index 290ms. لا يغني التشغيل المنفرد عن القياس المتكرر على المضيف الدائم.

**النتيجة الدقيقة:** تحققت 100 على الحاسوب، ولم تتحقق على الهاتف؛ Lighthouse CI للهاتف ما يزال يفشل سقوف FCP/LCP/JS والهدف 100. لم تُخفّض العتبات. معالجة الأداء على الهاتف تستمر في المرحلة 11، مع إبقاء التصميم ثابتاً.

## الخطوط والمراقبة

- IBM Plex Sans Arabic محلياً بملفات WOFF2 مقسمة للعربية/اللاتينية و`font-display: swap`؛ لا اتصال إلى Google Fonts. العنوان الأول يستخدم Arial system لتقليل تأخر رسمه؛ بقية الواجهة تستخدم IBM Plex.
- Vercel Analytics وSpeed Insights مثبتان لكن غير مفعّلين لعدم وجود نشر دائم. Sentry اختياري ويتطلب `SENTRY_DSN`.
- `bun run analyze` لتحليل الحزمة و`bun run lighthouse` لقياس الهاتف.
