# تسليم MultiStore — المراحل 1–6

تاريخ الفحص: 10 أكتوبر 2026. هذه الحزمة تحتوي مصدر المشروع والـmigrations والاختبارات والوثائق، ولا تحتوي قاعدة بيانات أو بيانات اعتماد.

## ما تم تنفيذه والتحقق منه

- صفحة Landing العربية المعتمدة، الخطوط الذاتية، الوضع الداكن وبطاقة التحليلات التوضيحية.
- أساس PostgreSQL/Prisma متعدد المستأجرين والمصادقة وRBAC.
- onboarding وإنشاء متجر وواجهة إعدادات الأقسام العشرة، مع تحقق Zod وفحوص ملكية المتجر قبل الكتابة.
- كتالوج عربي يسمح بإنشاء وتعديل وإدارة حالة المنتجات والفئات ضمن نطاق المتجر، وبإنشاء متغير افتراضي للمنتج الجديد.
- رفع ملف JPEG/PNG/WebP/AVIF حقيقي حتى 5MB مع فحص توقيع الملف، تخزين خارج `public/`، سجل `MediaAsset` ومسار عرض مرتبط بالمتجر.

### أدلة اختبار التكامل

جُهزت PostgreSQL محلية على Sandbox، وطُبقت migrations وشُغّل seed لمتجر عرض اصطناعي. جرى عبر واجهة التطبيق ثم التحقق من السجلات:

- حفظ الأقسام العشرة: الأساسي، الهوية، الإقليمي، التواصل، الشحن، الدفع، الضرائب، الشبكات الاجتماعية، SEO والمتقدم. انعكست الحقول الأساسية والإقليمية على سجل المتجر، ووجدت إعدادات SiteSetting الستة، ومنطقة شحن واحدة، وقاعدة ضريبة واحدة، وستة إعدادات دفع.
- إنشاء فئة ثم تغيير اسمها ومعرفها، تعطيلها وإعادة تفعيلها.
- إنشاء منتج مع ملف PNG، والتحقق من ظهور صورة عبر endpoint الخاص بالمتجر وربط أصل الوسائط به.
- تحرير اسم المنتج والمعرف والوصف والسعر والكمية؛ ثم تجربة الانتقال من المسودة إلى النشر، والأرشفة، والاستعادة إلى المسودة.
- أمكن التحقق قراءة فقط من القيم النهائية في PostgreSQL، بما فيها حالة المنتج المسودة والفئة النشطة وسجل الصورة.

الفحوص النهائية للمصدر: `bun run test` و`bun run typecheck` و`bun run lint` و`bun run build`.

## إعادة إعداد قاعدة عرض محلية

1. ثبّت Bun 1.2+ وPostgreSQL، ثم انسخ `.env.example` إلى `.env.local`.
2. اضبط `DATABASE_URL` و`DIRECT_URL` على قاعدة اختبار محلية منفصلة، وأنشئ قيماً عشوائية لـ`AUTH_SECRET` و`AUTH_RATE_LIMIT_SECRET`.
3. نفّذ:

```bash
bun install --frozen-lockfile
bun run db:generate
bun run db:migrate:deploy
ALLOW_DEMO_SEED=true bun run db:seed
bun run dev
```

لإنشاء مستخدم مالك اختبار جديد (غير مطلوب للبيانات الأساسية)، مرر `DEMO_OWNER_EMAIL` و`DEMO_OWNER_PASSWORD` في الأمر نفسه مع `ALLOW_DEMO_SEED=true`. كلمة المرور يجب أن تكون 12 حرفاً على الأقل. seed يرفض العمل عندما تكون `NODE_ENV=production`.

## ما لا تتضمنه الحزمة وما تبقى

- لا تحتوي `.env.local` أو الأسرار أو ملف حساب مالك الاختبار أو بيانات قاعدة PostgreSQL أو ملفات `var/uploads`؛ أُزيلت بيانات اعتماد مستخدم الاختبار من الحزمة.
- قاعدة البيانات التي اختُبرت قائمة داخل Sandbox وليست قاعدة مستضافة للمستخدم. تعليمات seed تعيد إنشاء بيانات اصطناعية من المصدر.
- تخزين الصور الحالي على القرص المحلي، وهو مناسب للتجربة فقط ما لم يُربط بمجلد دائم أو مخزن كائني في الاستضافة. Cloudinary والتحويلات السحابية غير مهيأة.
- لكل منتج متغير افتراضي أولي؛ واجهة إدارة عدة متغيرات/خيارات غير مكتملة.
- مراحل الطلبات والأدمن والمحتوى والمتجر العام والتحسين النهائي للهاتف والنشر الدائم (7–12) ما زالت لاحقة وفق [`ROADMAP.md`](ROADMAP.md).
- رابط المعاينة الحالي مؤقت، وليس نشرًا دائماً.
